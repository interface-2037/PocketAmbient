| D3 | 2026-10-09 | Host toolchain on Windows: **WinLibs GCC 16.2** (MinGW-w64 UCRT) + `mingw32-make`, installed with winget. `tools/env.sh` / `tools/env.ps1` add it to PATH. | D4 | 2026-10-09 | **Tick-boundary register semantics.** All composer writes during tick N take effect together at the first sample of the next 48-sample block; status reads return a snapshot taken at the tick boundary. On hardware this means shadow registers + a commit strobe, and the engine must not start block N+1 until the CPU acknowledges tick N (the FIFO absorbs the wait). | Without this, CPU timing jitter would change which sample a write lands on, which breaks host == RTL bit-exactness (spec §7 determinism). |
| D5 | 2026-10-09 | **Idle voices are frozen**: a voice whose envelope is IDLE with gate low does no state update at all (phases, filters, noise, slews). Triggering from IDLE resets filter/noise state, snaps slewed parameters to their targets and sets the oscillator phases (PAD: pseudo-random from the voice PRNG; others: 0). | Models RTL clock-gating (spec §1.2.6 power) and lets the host model skip idle voices without losing bit-exactness. Random PAD phase avoids a coherent summed peak when a chord starts (found as clipping + clicks in early DRIFT renders). |
| D6 | 2026-10-09 | **Envelopes** are one-pole exponential segments in Q1.30. Attack aims at 1.25 and stops at 1.0 (analog-style); decay/sustain is one state that tracks a live sustain level; release snaps to IDLE below ~-84 dB. Rates are a 16-bit code `exp4:mant12`, coefficient `(0x1000|mant) << exp`, time constant 16 samples … ~22 s. Attack up to 30 s and release up to 60 s are covered (tested). | One multiply per segment, no division in RTL, exponential (natural-sounding) curves. |
| D7 | 2026-10-09 | **Saw/tri oscillators use mip-mapped band-limited wavetables** (10 levels × 1024 × 16-bit for each shape, Lanczos-softened) instead of PolyBLEP. The mip level comes from the MSB of `phase_inc` (a priority encoder in RTL). | PolyBLEP needs a per-sample division by `phase_inc`; the tables need none, and they are alias-free by construction. Cost: 40 KB BRAM (see MEMORY_BUDGET.md). |
| D8 | 2026-10-09 | **SVF**: Chamberlin, 2× oversampled (same input twice), `f` clamped to ≤ 0.8 and `q` to [1/16, 2]. With these limits `f² + 2fq < 4`, so the filter is stable for every register value (the test sweeps the grid). | Spec §3.5. A clamp in hardware is cheaper than a TPT structure. |
| D9 | 2026-10-09 | **Reverb**: 8-line FDN with a **Householder** matrix (`y_i - (Σy)/4`: shifts and adds only), 4 Schroeder allpass diffusers (g = 0.625), pre-delay, lines 0 and 5 modulated ±8 samples by 0.31/0.43 Hz triangles. Delay memory is 16-bit in SRAM, round-to-nearest on write. | The Householder matrix is lossless and multiplier-free for N = 8. Rounding (not truncation) avoids DC creep in the tail. |
| D10 | 2026-10-09 | **Noise source**: 2 × one-pole high-pass at ~120 Hz (`lp += (w-lp) >> 6`), and the pink filter's first pole moved from 18 Hz to 80 Hz. New noise mode `NOISE_PDUST` (pink dust) for softer rain. HUSH wind and surf use a resonant **low-pass** rather than a band-pass. | The spec §8.3 spectral checks (<20 Hz < -40 dB, >16 kHz < -50 dB) failed on HUSH: a band-pass is only 6 dB/oct and the pink generator's sub-bass leaked through the low-passed beds. Measured after the change: -51.6 dB and -53.3 dB. |
| D11 | 2026-10-09 | **Master chain**: 2 × one-pole HPF at 25 Hz → trim (U2.14) → fade gain (linear ramp, applied squared) → soft clipper (knee -6 dBFS, ceiling -1.05 dBFS, tanh table) → TPDF dither → round. When the fade gain is exactly 0 the output is forced to 0 (dither off), so a stop ends in true digital silence. | Spec §3.5 master chain. |
| D12 | 2026-10-09 | Per-mode **loudness trims** in U2.14, calibrated to -20 LUFS (values live in each `mode_*.c` as `TRIM`; see D25). | Spec §8.3: -20 ± 3 LUFS, modes within ±2 LU. |
| D13 | 2026-10-09 | **Voice-leading bound**: each upper voice moves ≤ 7 semitones except in crowded windows (0.03% of moves measured), never more than 11. The register window is soft by ±4 semitones to avoid unisons. | An exact minimal-motion assignment search is too slow for one 1 ms tick on PicoRV32. The rare larger moves are inaudible as leaps because DRIFT voices crossfade over 6–20 s. |
| D14 | 2026-10-09 | Host render speed is **~90–140× realtime** (spec target ≥ 200×). An 8 h render takes ~5 min per mode, which is acceptable for nightly runs. | D15 | 2026-10-09 | The HUSH sub drone sits on the key's **modal centre** in A1–G#2 (spec says A1–E2). | It follows the harmony; G#2 is still a sub-ish register, and the 2nd harmonic keeps it audible on the speaker. |

| D45 | 2026-10-11 | **Voice engine (Phase 2b): a modulo-scheduled pipeline.** A new active voice enters every **II = 10 cycles** and is in flight for 49 cycles (up to 5 voices at once), so 32 active voices take **~360 of the 1,546 cycles** per sample. Frozen voices are skipped. Four 33×33 multipliers (four registered 17-bit partial products each, 2 DSPs, 3-cycle latency) and the table ports (sine A/B, wavetable saw+tri A/B, pluck line) are booked in a per-phase reservation table, so each unit is used at most once per phase. Algorithms share a slot only at the same offset. Table reads take 2 cycles (M10K address + output register) plus 2 for interpolation (`ve_interp`). Voice registers and voice state are in 8-bank RAMs whose rows are ordered by when the schedule needs them. Values that cross a 10-cycle stage live in 5-entry arrays that shift at phase 9. **Standalone fit: 4,846 ALMs (26 %), 6,805 registers, 112 M10K, 19 DSP, Fmax 80.3 MHz** (slow 85 °C model; target 74.25 MHz, worst slack +1.23 ns on the filter mode-select path). | The first re-timed version (one voice at a time, 34 cycles/voice, single-stage 33×33 multipliers, unregistered RAM outputs) was bit-exact but reached only 42 MHz and 1,088 cycles worst case. The pipeline is both faster and 3× more efficient per cycle. Both pass the same golden vectors; `voice_engine_ref.sv` (Phase 2a) remains the readable reference. |

| D48 | 2026-10-12 | **Phase 4 CPU integration** (`src/fpga/core/cpu/cpu_sys.sv`). **Firmware:** clang + lld (`--target=riscv32 -march=rv32imc -Os`, freestanding), `fw/rv/` holds `crt0.S` (stack, zero `.bss` on every CPU reset), `link.ld` (64 KB at 0; `.data` must stay empty so a CPU reset without a reload is safe), `rt.c` (memset/memcpy, 64-bit division on the hardware DIVU) and `main.c`. `make fw` writes `src/fpga/core/cpu/composer.hex` (committed, like the other ROM files).
